## 指标 — Class 图表

### 1. Co-Purchase Cross-Sell-Class Value

```dax
Co-Purchase Cross-Sell-Class Value = 
// ========================================
// 度量值: Co-Purchase Cross-Sell-Class Value
// 用途: Class 图表的连带率，按 Slicer_Co_Purchase_Type_Selection 切换 Same-Order / Cross-Order 公式
// 分支 Same-Order:  sum(co_net_pay_order_cnt) / sum(net_pay_order_cnt)（直接聚合）
// 分支 Cross-Order: 同Same-Order逻辑
// 数据底表: a03_e2e_customer_order_correlation_data_m
// 筛选处理: 时间/周期/类型由模型关系自动传递；
// 行维度: co_category_summary 直接拉取，自动分组
// 数据格式: percent_0dp（Display 层处理）
// ========================================
// 获取当前上下文的行和列值
VAR __CurrentCategory_Summary = SELECTEDVALUE(Dim_Category_Summary[category_summary])
VAR __CurrentCo_Category_Summary = SELECTEDVALUE(Dim_Co_Category_Summary[co_category_summary])
VAR __co_net_pay_order_cnt = 
    CALCULATE(
        SUM('a03_e2e_customer_order_correlation_data_m'[co_net_pay_order_cnt]),
        a03_e2e_customer_order_correlation_data_m[category_summary] = __CurrentCategory_Summary,
        a03_e2e_customer_order_correlation_data_m[co_category_summary] = __CurrentCo_Category_Summary
    )
VAR __net_pay_order_cnt = 
    CALCULATE(
        SUM('a03_e2e_customer_order_correlation_data_m'[net_pay_order_cnt]),
        a03_e2e_customer_order_correlation_data_m[category_summary] = __CurrentCategory_Summary,
        a03_e2e_customer_order_correlation_data_m[co_category_summary] = __CurrentCo_Category_Summary
    )

RETURN
    DIVIDE(
                __co_net_pay_order_cnt,
                __net_pay_order_cnt
            )
```

### 3. Is_Matrix_Row_Visible_Category

```dax
Is_Matrix_Row_Visible_Category = 
// ========================================
// 用途：严格按度量值结果判断，当前 Category_Summary (行) 是否至少有一个 Co_Category_Summary (列) 有真实数据
// 返回值：1 (显示该行), 0 (隐藏该行)
// ========================================

VAR __CurrentCategory = SELECTEDVALUE(Dim_Category_Summary[category_summary])

// 获取当前筛选上下文下，所有可见的 Co_Category_Summary 列表
VAR __AllVisibleCoCategories = ALLSELECTED(Dim_Co_Category_Summary[co_category_summary])

// 迭代检查：遍历这一行所有的 Co_Category_Summary
VAR __HasValidDataInRow = 
    MAXX(
        __AllVisibleCoCategories,
        VAR __CurrentCoCategory = Dim_Co_Category_Summary[co_category_summary]
  
        // 严格复刻单元格计算逻辑
        VAR __CellResult = 
            CALCULATE(
                [Co-Purchase Cross-Sell-Class Value], 
                'a03_e2e_customer_order_correlation_data_m'[category_summary] = __CurrentCategory,
                'a03_e2e_customer_order_correlation_data_m'[co_category_summary] = __CurrentCoCategory
            )
    
        RETURN
            IF(NOT ISBLANK(__CellResult), 1, 0)
    )

RETURN
    IF(__HasValidDataInRow = 1, 1, 0)
```

### 5. Co-Purchase Cross-Sell-Class SVG
```dax
Co-Purchase Cross-Sell-Class SVG = 
// ========================================
// 度量值: Co-Purchase Cross-Sell-Class SVG
// 用途: 热力矩阵图单元格，背景/字体颜色按值四点三段插值自适应
// 背景插值: 0%→#d8dee5, 30%→#95afcf, 50%→#0c2340, 100%→#000000

// ========================================

VAR _IsBlank = ISBLANK(_RawValue)
VAR _Value = MIN(MAX(_RawValue, 0), 1)
VAR _Pct = FORMAT(_Value, "#,##0%;#,##0%;0%")

// ── 2. 背景颜色三段插值（0%→30%→50%→100%）──
// 0%: #d8dee5 = rgb(216,222,229)
// 30%: #95afcf = rgb(149,175,207)
// 50%: #0c2340 = rgb(12,35,64)
// 100%: #000000 = rgb(0,0,0)
VAR _BR0 = 216
VAR _BG0 = 222
VAR _BB0 = 229

VAR _BR30 = 149
VAR _BG30 = 175
VAR _BB30 = 207

VAR _BR50 = 12
VAR _BG50 = 35
VAR _BB50 = 64

VAR _BR100 = 0
VAR _BG100 = 0
VAR _BB100 = 0

VAR _BR = IF(
    _Value <= 0.3,
    _BR0 + (_BR30 - _BR0) * (_Value / 0.3),
    IF(
        _Value <= 0.5,
        _BR30 + (_BR50 - _BR30) * ((_Value - 0.3) / 0.2),
        _BR50 + (_BR100 - _BR50) * ((_Value - 0.5) / 0.5)
    )
)
VAR _BG = IF(
    _Value <= 0.3,
    _BG0 + (_BG30 - _BG0) * (_Value / 0.3),
    IF(
        _Value <= 0.5,
        _BG30 + (_BG50 - _BG30) * ((_Value - 0.3) / 0.2),
        _BG50 + (_BG100 - _BG50) * ((_Value - 0.5) / 0.5)
    )
)
VAR _BB = IF(
    _Value <= 0.3,
    _BB0 + (_BB30 - _BB0) * (_Value / 0.3),
    IF(
        _Value <= 0.5,
        _BB30 + (_BB50 - _BB30) * ((_Value - 0.3) / 0.2),
        _BB50 + (_BB100 - _BB50) * ((_Value - 0.5) / 0.5)
    )
)
VAR _BgColor = "rgb(" & INT(_BR) & "," & INT(_BG) & "," & INT(_BB) & ")"

// ── 3. 字体颜色三段插值（0%→30%→35%→100%，白色提前到35%）──
// 0%: #737373 = rgb(115,115,115)
// 30%: #333333 = rgb(51,51,51)
// 35%: #ffffff = rgb(255,255,255)  ← 白色节点从50%提前到35%
// 100%: #ffffff = rgb(255,255,255)
VAR _FR0 = 115
VAR _FG0 = 115
VAR _FB0 = 115

VAR _FR30 = 51
VAR _FG30 = 51
VAR _FB30 = 51

VAR _FR35 = 255
VAR _FG35 = 255
VAR _FB35 = 255

VAR _FR100 = 255
VAR _FG100 = 255
VAR _FB100 = 255

VAR _FR = IF(
    _Value <= 0.3,
    _FR0 + (_FR30 - _FR0) * (_Value / 0.3),
    IF(
        _Value <= 0.35,
        _FR30 + (_FR35 - _FR30) * ((_Value - 0.3) / 0.05),
        _FR35 + (_FR100 - _FR35) * ((_Value - 0.35) / 0.65)
    )
)
VAR _FG = IF(
    _Value <= 0.3,
    _FG0 + (_FG30 - _FG0) * (_Value / 0.3),
    IF(
        _Value <= 0.35,
        _FG30 + (_FG35 - _FG30) * ((_Value - 0.3) / 0.05),
        _FG35 + (_FG100 - _FG35) * ((_Value - 0.35) / 0.65)
    )
)
VAR _FB = IF(
    _Value <= 0.3,
    _FB0 + (_FB30 - _FB0) * (_Value / 0.3),
    IF(
        _Value <= 0.35,
        _FB30 + (_FB35 - _FB30) * ((_Value - 0.3) / 0.05),
        _FB35 + (_FB100 - _FB35) * ((_Value - 0.35) / 0.65)

// ── 4. BLANK 处理：置灰显示 "-" ──

VAR _URL =
```

## 原理详解：隐藏全空行列，同时保留 SVG 内部空白占位

### 1. 适用场景与 Class／Label 字段对应

本节解释上文 SVG 最后一步的判断原理。为便于理解，使用 Label 版本的 Brand／CoBrand 举例；Class 版本与其逻辑相同，只是字段和度量名称不同。

适用前提：行、列均为单层维度，与事实表断开连接；Value 度量通过 `SELECTEDVALUE` 读取行列值，再用 `CALCULATE` 显式筛选事实表；可见性度量从 SVG 明细单元格内部调用。

| 对象 | Class 版本（本文上方实现） | Label 版本（本节解释示例） |
| --- | --- | --- |
| 行字段 | `Dim_Category_Summary[category_summary]` | `Dim_Brand[brand]` |
| 列字段 | `Dim_Co_Category_Summary[co_category_summary]` | `Dim_Co_Brand[co_brand]` |
| 基础值 | `[Co-Purchase Cross-Sell-Class Value]` | `[Co-Purchase Cross-Sell-Label Value]` |
| 行可见性 | `[Is_Matrix_Row_Visible_Category]` | `[Is_Matrix_Row_Visible_Brand]` |
| 列可见性 | `[Is_Matrix_Col_Visible_CoCategory]` | `[Is_Matrix_Col_Visible_CoBrand]` |

Label 原始实现参见 [Co-Purchase Trend.md 的 4.2 部分](../RL%20E2E%20Customer%20Dashboard/Customer/Co-Purchase/Co-Purchase%20Trend.md)。

### 2. 三层判断分别负责什么

| 判断或返回值 | 职责 | 不代表什么 |
| --- | --- | --- |
| `__IsDetailCell` | 判断当前是否为行列交叉明细，排除总计位置 | 不代表有业务数据 |
| 行可见性 = 1 且列可见性 = 1 | 判断当前所在行、列是否分别存在非空 Value | 不代表当前交叉点非空，也不是唯一性判断 |
| SVG 返回 `BLANK()` | 让无效行／列上的单元格真正为空，由矩阵隐藏全空行列 | 不等于绘制一张看起来空白的图片 |

**为什么单独放 Value 能隐藏全空行列，换成 SVG 后原来不行？**

如果 SVG 无条件 `RETURN _URL`，即使基础值为空，仍会返回绘制灰色 `"-"` 的图片字符串。Power BI 判断的是度量返回值是否为 `BLANK()`，不会把图片里的短横线识别为“无数据”。

| 基础业务值 | Value 返回值 | 无条件返回 `_URL` 时的 SVG 返回值 |
| --- | --- | --- |
| 有值 | 数字 | 百分比图片字符串，非空 |
| 无值 | `BLANK()` | 灰色 `"-"` 图片字符串，仍然非空 |

因此，需要让全空行列对应的 SVG 单元格返回真正的 `BLANK()`，只在有效行列内部保留空白占位图片。

### 3. ISINSCOPE 只判断明细层级，不判断空值

```dax
// 判断当前计算位置是否为 Brand × CoBrand 的交叉明细。
// 注意：这里只检查分组层级，不检查业务数据是否为空。
// 即使当前交叉点没有事实记录，两个 ISINSCOPE 仍可以为 TRUE。
// 用途是排除行方向合计、列方向合计及整个矩阵总计。
VAR __IsDetailCell =
    ISINSCOPE(Dim_Brand[brand])
        && ISINSCOPE(Dim_Co_Brand[co_brand])
```

**对于当前单层矩阵：**

| 当前计算位置 | `ISINSCOPE(brand)` | `ISINSCOPE(co_brand)` | `__IsDetailCell` |
| --- | --- | --- | --- |
| Brand=A、CoBrand=X，业务有值 | TRUE | TRUE | TRUE |
| Brand=A、CoBrand=X，业务为空 | TRUE | TRUE | TRUE |
| Brand=A、所有 CoBrand 的合计 | TRUE | FALSE | FALSE |
| 所有 Brand 的合计、CoBrand=X | FALSE | TRUE | FALSE |
| 整个矩阵总计 | FALSE | FALSE | FALSE |

普通交叉单元格不管有没有业务数据，两个 `ISINSCOPE` 都是 `TRUE`。因此，把行列字段放入矩阵以后，普通单元格确实都会通过这一判断；真正筛掉全空行列的是后续可见性逻辑与 `BLANK()` 返回值。

如果关闭全部总计，这个变量仍可作为明细保护条件，但不是隐藏全空行列的核心条件。

`ISINSCOPE` 与 `SELECTEDVALUE` 也不是同一概念：即使切片器只选择了一个 Brand，总计位置的 `SELECTEDVALUE(brand)` 可能有值，但该位置的 `ISINSCOPE(brand)` 仍可以为 `FALSE`。不能用“能否取得单值”代替“是否处于明细层级”。

### 4. 为什么行有效与列有效需要同时满足

```dax
[Is_Matrix_Row_Visible_Brand] = 1
    && [Is_Matrix_Col_Visible_CoBrand] = 1
```

两个条件分别表示：

- **行可见性 = 1**：固定当前 Brand，在外部选择范围内，至少有一个 CoBrand 对应的 Value 非空。
- **列可见性 = 1**：固定当前 CoBrand，在外部选择范围内，至少有一个 Brand 对应的 Value 非空。

**两处非空数据可以出现在不同单元格，不要求当前交叉点有值。**

#### 4.1 基础值示例

以下 A／B／C、X／Y／Z 与百分比均为说明逻辑的示意数据，不是实际业务数据。

| Brand \ CoBrand | X | Y | Z |
| --- | --- | --- | --- |
| A | 20% | BLANK | BLANK |
| B | BLANK | 30% | BLANK |
| C | BLANK | BLANK | BLANK |

目标：保留 A、B 两行与 X、Y 两列，隐藏全空的 C 行和 Z 列；保留 A × Y、B × X 的灰色空白占位。

#### 4.2 看几个交叉点

| 当前单元格 | 当前 Value | 所在行有效 | 所在列有效 | SVG 应返回 |
| --- | --- | --- | --- | --- |
| A × X | 20% | 1 | 1 | 百分比 SVG |
| A × Y | BLANK | 1，A × X 有值 | 1，B × Y 有值 | 灰色 `"-"` SVG |
| B × X | BLANK | 1，B × Y 有值 | 1，A × X 有值 | 灰色 `"-"` SVG |
| A × Z | BLANK | 1 | 0 | `BLANK()` |
| C × X | BLANK | 0 | 1 | `BLANK()` |
| C × Z | BLANK | 0 | 0 | `BLANK()` |

A × Y 虽然自身为空，但所在行 A、所在列 Y 都有保留的理由，所以继续绘制灰色占位；A × Z 所在的 Z 列全空，必须返回真正的 `BLANK()`。

过滤后，矩阵逻辑上呈现为下表；实际单元格仍使用原有 SVG 颜色、圆角和字体：

| Brand \ CoBrand | X | Y |
| --- | --- | --- |
| A | 20% SVG | 灰色 `"-"` SVG |
| B | 灰色 `"-"` SVG | 30% SVG |

#### 4.3 只检查一个条件会怎样

| 判断方式 | 示例中的后果 |
| --- | --- |
| 只判断行有效 | A × Z、B × Z 会生成灰色图片，导致全空 Z 列被保留 |
| 只判断列有效 | C × X、C × Y 会生成灰色图片，导致全空 C 行被保留 |
| 行有效与列有效使用 `&&` | 同时排除以上两种情况，保留有效行列内部的空占位 |
| 行有效或列有效使用 OR | 任一方向有效就生成图片，无法同时排除全空行列 |

在这套“同时隐藏全空行列、保留内部空白占位”的实现中，需要同时满足两个条件。它们不用于确认唯一单元格：当前位置已由矩阵的行列筛选上下文确定，背后可能对应多条事实记录。

如果完全不需要内部灰色占位，可以直接使用 `IF(_IsBlank, BLANK(), _URL)`，这时无需扫描两个方向，但内部空单元格也不会再绘制 SVG。

### 5. 两个可见性度量的上下文与正确性

在当前“断开维度、单层矩阵、从 SVG 明细单元格内部调用”的条件下，现有两个辅助度量的核心逻辑正确。

#### 5.1 行度量：固定当前行，逐列检查

以正在计算 A × X 的单元格为例，外部选择范围内的候选列是 X、Y、Z：

1. `__CurrentBrand` 保存当前行 A。
2. `ALLSELECTED(Dim_Co_Brand[co_brand])` 提供 X、Y、Z 候选列，而不是只检查当前矩阵列 X。
3. `MAXX` 迭代到 Y 时，产生 `Dim_Co_Brand[co_brand] = Y` 的迭代行上下文。单靠行上下文，还不会改变 `SELECTEDVALUE` 的结果。
4. 内部 `CALCULATE` 执行上下文转换，把 Y 转成维度列筛选，替换原来的当前列 X 筛选；未扫描的 Brand=A 保持不变。
5. `[Co-Purchase Cross-Sell-Label Value]` 重新求值，其两个 `SELECTEDVALUE` 得到 A、Y。
6. Value 内部把 A、Y 映射到事实表 `brand`、`co_brand`，计算这个交叉点；日期等其他筛选继续保留。
7. 每个结果非空返回 1，空返回 0；`MAXX` 只要取得一个 1，当前行就有效。最后的 `IF(... = 1, 1, 0)` 保证候选集合为空时也返回 0。

```text
固定 Brand=A：
    检查 A × X → 非空返回 1，否则返回 0
    检查 A × Y → 非空返回 1，否则返回 0
    检查 A × Z → 非空返回 1，否则返回 0

MAXX 取最大值：只要存在一个 1，整行就有效。
```

**关键是“遍历维度列 + 上下文转换”，不是事实表条件反向筛选了断开的维度表。**

#### 5.2 列度量：固定当前列，逐行检查

列度量与行度量完全对称：固定 CoBrand=X，使用 `ALLSELECTED(Dim_Brand[brand])` 遍历 A、B、C，分别重新计算 A × X、B × X、C × X；只要其中一个 Value 非空，该列就有效。

#### 5.3 审查结论与边界

- 辅助度量中设置事实表 `brand/co_brand` 条件，与 Value 内部的条件在当前上下文中一致，属于重复设置，不是错误，也没有必须删除的理由。
- `ALLSELECTED` 取得的是外部选择上下文中的候选成员，不是 SVG 隐藏完成后屏幕上最终剩余的成员清单。
- 判断口径是 **Value 非空**，不是“事实表存在记录”。`0%` 属于有效值；分母为零导致 `DIVIDE` 返回空时，按无效值处理。
- Value 必须在每次迭代中重新求值，不能先在迭代器外保存成标量变量，再把该变量当作每个交叉点的结果。
- 以后若加入多级行列、排序列带来的额外筛选或 Top N 等，需要重新核验扫描范围；单列 `ALLSELECTED` 不会自动清除同表其他列上的限制。
- 辅助度量在 SVG 单元格中执行时有当前行列上下文；不能把这一结论直接推广到视觉对象级度量筛选器。原生矩阵的度量筛选粒度由行字段决定，交换字段不会使筛选器自动变为按列筛选。

### 6. SVG 返回部分的详细注释版

下面是 **Label SVG 末尾片段**，不是独立的新度量。保留原度量前面的 `_RawValue`、`_IsBlank`、颜色计算及 `_URL`，用下面片段替换原第 6 步和最终 `RETURN`，不要重复追加第二个 `RETURN`。

若用于本文上方的 Class SVG，将行列字段和两个辅助度量按第 1 节对应表替换；其余逻辑不变。

```dax
// ── 6. 判断当前计算位置 ──
// 两个字段都处于分组层级，表示当前是 Brand × CoBrand 交叉明细。
// 这里只区分明细与总计，不检查当前单元格是否存在业务数据。
VAR __IsDetailCell =
    ISINSCOPE(Dim_Brand[brand])
        && ISINSCOPE(Dim_Co_Brand[co_brand])

RETURN
    IF(
        NOT __IsDetailCell,

        // 情况一：总计位置。
        // 不绘制 SVG，也不使用仅适用于明细的行列可见性判断。
        BLANK(),

        IF(
            _IsBlank,

            // 情况二：当前交叉点的基础 Value 为空。
            // 不能直接绘制灰色图片，否则全空行列也会被图片保留下来。
            // 必须分别检查当前交叉点所在的整行、整列是否应当保留。
            IF(
                // 行有效：固定当前 Brand，
                // 扫描所选 CoBrand，至少一个 Value 非空。
                [Is_Matrix_Row_Visible_Brand] = 1

                    // 列有效：固定当前 CoBrand，
                    // 扫描所选 Brand，至少一个 Value 非空。
                    && [Is_Matrix_Col_Visible_CoBrand] = 1,

                // 行列均有效：
                // 当前空值属于有效矩阵内部的缺口，保留灰色 "-" SVG。
                _URL,

                // 行全空或列全空：
                // 返回真正的 BLANK()，而不是空白图片或 "-" 字符串。
                // 该无效行／列上的每个单元格都会因此返回 BLANK()，
                // 由矩阵自身的空值抑制机制隐藏整行或整列。
                BLANK()
            ),

            // 情况三：当前交叉点的基础 Value 非空。
            // 当前单元格本身已证明所在行、所在列都有有效数据，
            // 无需再扫描两个方向，直接绘制百分比 SVG。
            // 0% 也属于非空有效值，会正常保留。
            _URL
        )
    )

// 结果摘要：
// 总计位置 → BLANK()
// 明细有值 → 百分比 SVG
// 明细为空，但所在行列均有效 → 灰色 "-" SVG
// 明细为空，且所在行或列全空 → BLANK()
```

### 7. 视觉对象配置与验证

1. 矩阵行、列使用第 1 节中同一版本的维度字段，“值”区域使用相应 SVG 度量，数据类别设置为 `Image URL`。
2. 行、列字段都关闭“显示无数据的项”。
3. 两个可见性度量由 SVG 内部调用，不再配置为视觉对象筛选条件，也不要放进正式矩阵的“值”区域。
4. 不要同时展示将空值转为 `"-"` 的 Display 度量，否则非空文本可能继续保留全空行列。
5. 对照第 4 节示例：C 行与 Z 列消失，A × Y、B × X 仍显示灰色占位；有效的 0% 和既有 SVG 样式保留；总计不绘制 SVG。
6. 切换日期、行列类别等筛选，确认保留范围随基础 Value 变化，辅助度量只检查当前外部选择范围内的候选成员。
7. 如需调试，复制矩阵并临时放入 Value 和两个可见性度量，核对 0/1。辅助度量返回的 0/1 本身非空，调试矩阵会保留空行列；验证后移除，不能用调试状态判断最终隐藏效果。

性能方面，本方案把行列扫描放在当前 Value 为空的分支；有值单元格直接返回 SVG。较大矩阵仍可能因大量空交叉点的扫描增加开销，应通过 Performance Analyzer 测量，不能仅凭代码结构断言实际加速比例。

验证范围：Class 版本已获用户实测确认，能够隐藏全空行列并保留 SVG；Label 的上下文与返回逻辑已做静态审查，实际显示仍需在对应报表中验证。本节示意表用于解释判断过程，不代替真实模型测试。

**总结：`ISINSCOPE` 决定“这里是不是明细”；两个可见性度量决定“这行和这列是否值得保留”；真正让全空行列消失的是 SVG 最终返回 `BLANK()`。**

# 动态行维度、动态指标与联动排序 Demo 解决方案

## 1. 目标与实现范围

在 Power BI Desktop 中使用原生**表格**和四个切片器，实现以下交互，不依赖数据库、Excel、自定义视觉对象或外部服务。

| 控件          | 作用                                               | Demo 选项                             | 选择方式 |
| ------------- | -------------------------------------------------- | ------------------------------------- | -------- |
| A：展示行维度 | 改变表格按什么字段分组；多选时按参数顺序形成行层级 | 门店、区域、店铺类型                  | 多选     |
| B：展示指标   | 改变表格展示哪些业务指标列                         | 净销售额、总销售额、净销售额/总销售额 | 多选     |
| C：排序指标   | 决定按哪个业务指标排列当前行                       | 候选受 B 限制                         | 单选     |
| D：排序方向   | 决定业务指标升序或降序                             | 升序、降序                            | 单选     |

例如：A 选“门店”，B 选“净销售额、总销售额”，C 选“总销售额”，D 选“降序”，表格按门店汇总，只展示这两个业务指标，并按总销售额从高到低排列。

A 多选“区域 + 门店”时，表格按区域分组展示门店行，序号在每个区域组内从 1 重新编号，C、D 仍驱动组内排序；A 只选一个维度时序号即全局连续序号。

### 1.1 Demo 业务口径

- 净销售额：示例事实表 `Net_Sales_Amount` 求和；含多笔负数调整记录（门店 E、H），用于展示净额汇总与负值排序。
- 总销售额：示例事实表 `Gross_Sales_Amount` 求和。
- 比值：**当前分组净销售额合计 ÷ 当前分组总销售额合计**，不是逐笔或逐门店比值的平均数。
- 金额单位：人民币元，显示两位小数；比值显示一位小数百分比。
- 分母为 0 时比值返回 `BLANK()`，不伪造为 0%。净额为 0、分母非零时返回真实的 0%。
- 同值按当前分组包含的最小 `Store_ID` 升序决胜；该规则对升序、降序一致。
- 排序指标为空的行始终放在末尾。零值行保留，不沿用其他业务模块的零值隐藏规则。
- A 支持单选与多选行维度**字段**（不是行成员多选）。多选时按参数表顺序形成行层级（区域 → 店铺类型 → 门店，粗 → 细），每个父组内独立排序，序号在每组内从 1 重新编号；组与组之间的先后顺序按外层字段的默认排序，不再按业务指标排序。行成员筛选、父级小计行不在本 Demo 范围。

### 1.2 三个必须说明的原生限制

**限制一：DAX 不能直接修改视觉对象的“按哪一列排序、升序还是降序”设置。**

解决方式是在表格里保留一列辅助的“排序序号”，视觉对象始终按它升序。C、D 改变的是序号的计算结果，因此表格的业务行顺序随之改变。这不是新增业务指标，B 中仍然只有三个指标。

不要把辅助列从表格字段区域移除，也不要依赖把宽度缩成 0 的隐藏技巧。用户点击其他业务列头会覆盖视觉排序，此时需重新按“排序序号”升序。

**限制二：筛选 C 的候选项，不等于清除或改写 C 已保存的选择。**

当 B 取消 C 当前选中的指标时，原生切片器可能保留旧选择；部分切片器版本还可能保留显示旧选项。即使开启按钮切片器的 Force selection，也不会自动选中第一个可见项。

本方案采用两层控制：

1. C 视觉筛选度量限制可用候选；正常交互下只能从 B 已选指标中选择。
2. 每次计算实际排序指标时，再验证 C 选择是否属于 B。不属于时，按 B 当前可用指标的固定顺序选择第一个，并通过状态卡说明。

**保证的是：实际用于排序的指标始终来自 B。不能承诺：B 一变化，C 的勾选标记也自动同步为回退项。** 若要求 C 的勾选状态必须强制实时同步，单靠此原生方案不能完整保证，需另外开发能够控制选择状态的自定义交互。

**限制三：矩阵视觉对象的行顺序无法按度量值排序。**

多选行维度最自然的容器是矩阵，但矩阵的行只能按行字段自身的“按列排序”设置排列，不能像表格那样按“排序序号”度量升序排列；若改用矩阵，C、D 的选择将无法驱动行顺序。因此本方案继续使用表格，配合字段参数多选与“渐变布局”（Stepped layout）实现层级外观与动态排序的共存。

本文件是独立 Demo 的搭建方案，不修改现有业务报表；不包含已经运行的 PBIX。末尾区分了脚本核验与待 Desktop 实测事项。

## 2. 最终页面与架构

仍然使用表格而不是矩阵：矩阵虽然原生支持层级展开，但其行顺序无法按度量排序（见 1.2 限制三），C、D 会失去作用；表格配合字段参数多选与“渐变布局”同样呈现层级外观，且支持按“排序序号”度量升序排列，同时保留各指标的原生数值格式。多选时字段参数按 Row_Order 顺序展开为多个行分组列（区域最左、门店最右），每个叶子行是各层字段值的组合。

```text
[A 展示行维度]  [B 展示指标，多选]  [C 排序指标]  [D 排序方向]

[状态卡：当前按“净销售额”降序；同值按分组最小门店 ID 升序]

排序序号 | 门店  | 净销售额 | 总销售额
1        | 门店K | 1,300.00 | 2,000.00
2        | 门店A |   900.00 | 1,200.00
3        | 门店C |   900.00 | 1,500.00
4        | 门店B |   800.00 | 1,000.00
5        | 门店G |   800.00 |   900.00
6        | 门店D |   500.00 |   800.00
7        | 门店I |   450.00 | 1,200.00
8        | 门店L |   300.00 |   600.00
9        | 门店E |     0.00 |   200.00
10       | 门店F |     0.00 |     0.00
11       | 门店J |     0.00 |     0.00
12       | 门店H |  -100.00 |   300.00
```

A 多选“区域 + 门店”时（C=净销售额，D=降序）：

```text
排序序号 | 区域 | 门店  | 净销售额 | 总销售额
1        | 华东 | 门店A |   900.00 | 1,200.00
2        | 华东 | 门店B |   800.00 | 1,000.00
3        | 华东 | 门店G |   800.00 |   900.00
4        | 华东 | 门店H |  -100.00 |   300.00
1        | 华南 | 门店C |   900.00 | 1,500.00
2        | 华南 | 门店D |   500.00 |   800.00
3        | 华南 | 门店I |   450.00 | 1,200.00
4        | 华南 | 门店J |     0.00 |     0.00
1        | 华北 | 门店K | 1,300.00 | 2,000.00
2        | 华北 | 门店L |   300.00 |   600.00
3        | 华北 | 门店E |     0.00 |   200.00
4        | 华北 | 门店F |     0.00 |     0.00
```

多选时组间先后顺序（华东、华南、华北谁先谁后）由外层字段的默认排序决定，与 C、D 无关。

共 6 张表、11 个度量、6 个视觉对象：

| 对象                             | 用途                             | 是否关联事实表 |
| -------------------------------- | -------------------------------- | -------------- |
| `Dim_Demo_Store`               | 门店属性，提供三个可切换的行维度 | 是             |
| `Fact_Demo_Sales`              | 42 条虚构明细记录                | 事实表         |
| `O：Param_Demo_Row`            | A 的行字段参数                   | 否             |
| `O：Param_Demo_Metric`         | B 的度量字段参数                 | 否             |
| `O：Slicer_Demo_SortMetric`    | C 的排序指标选项                 | 否             |
| `O：Slicer_Demo_SortDirection` | D 的排序方向选项                 | 否             |

数据关系只有一条：

```text
Dim_Demo_Store[Store_ID]  1 ────── *  Fact_Demo_Sales[Store_ID]
                           单向
```

四张控制表均断开关系，不在 B 与 C 之间建立双向关系。B 对 C 的限制由度量和视觉交互实现，C 不反向缩小 B 的展示指标集合。

## 3. 创建小型示例数据源

新建空白 Power BI 文件，依次在“建模 → 新建表”中创建以下两张计算表。数据是虚构的静态 Demo 数据，不需要数据源凭据或网关。

### 3.1 门店维度：12 行

```dax
Dim_Demo_Store =
    DATATABLE(
        "Store_ID", INTEGER,
        "Store_Name", STRING,
        "Region", STRING,
        "Store_Type", STRING,
        {
            // ── v1.0 原有 6 家门店（数值与 v1.0 完全一致，作为回归基准）──
            { 10, "门店A", "华东", "直营店" },
            { 20, "门店B", "华东", "加盟店" },
            { 30, "门店C", "华南", "直营店" },
            { 40, "门店D", "华南", "加盟店" },
            { 50, "门店E", "华北", "直营店" },
            { 60, "门店F", "华北", "加盟店" },
            // ── v1.2 新增 6 家门店（ID 70–120）──
            { 70, "门店G", "华东", "直营店" },
            { 80, "门店H", "华东", "加盟店" },
            { 90, "门店I", "华南", "直营店" },
            { 100, "门店J", "华南", "加盟店" },
            { 110, "门店K", "华北", "直营店" },
            { 120, "门店L", "华北", "加盟店" }
        }
    )
```

`Store_ID` 全局唯一，`Store_Name` 在此 Demo 中也唯一。每家门店只属于一个区域、一种店铺类型，因此任意分组的最小门店 ID 可以作为稳定的同值决胜键。新增门店 ID 均大于原有门店，同值决胜时原有门店始终排在新门店之前。

**不要给 `Store_Name`、`Region`、`Store_Type` 另外设置“按列排序”辅助列。** 后面的排名关系只枚举当前分组字段；额外隐藏排序列可能残留当前行筛选，影响候选集。本方案的行顺序统一交给排序序号度量。多选组内序号使用列级 `ALLSELECTED`，该写法成立的前提正是行字段没有按列排序辅助列；如未来新增，必须重新验证（参见第 11 节排错）。

### 3.2 销售事实表：42 行

每行是一条销售或调整记录。数据是一个整体样本，不包含时间分析需求，因此不添加日期字段和日期表。

```dax
Fact_Demo_Sales =
    DATATABLE(
        "Record_ID", INTEGER,
        "Store_ID", INTEGER,
        "Net_Sales_Amount", CURRENCY,
        "Gross_Sales_Amount", CURRENCY,
        {
            // ── v1.0 原有 12 条记录（数值与 v1.0 完全一致，作为回归基准）──
            { 101, 10,  500, 700 },
            { 102, 10,  400, 500 },
            { 103, 20,  600, 700 },
            { 104, 20,  200, 300 },
            { 105, 30,  450, 700 },
            { 106, 30,  450, 800 },
            { 107, 40,  250, 400 },
            { 108, 40,  250, 400 },
            { 109, 50,  100, 150 },
            { 110, 50, -100,  50 },
            { 111, 60,    0,   0 },
            { 112, 60,    0,   0 },
            // ── v1.2 新增 30 条记录（Record_ID 113–142）──
            // 门店G：净额与门店B 同为 800，验证净额同值决胜（B 在前）
            { 113, 70,  300, 350 },
            { 114, 70,  250, 300 },
            { 115, 70,  150, 150 },
            { 116, 70,   50,  50 },
            { 117, 70,   50,  50 },
            // 门店H：净额合计为负（-100），验证负值在升序最前、降序最后
            { 118, 80,  100, 150 },
            { 119, 80,   50, 100 },
            { 120, 80, -100,   0 },
            { 121, 80, -100,  50 },
            { 122, 80,  -50,   0 },
            // 门店I：总销售额与门店A 同为 1,200，验证总额同值决胜（A 在前）
            { 123, 90,  150, 400 },
            { 124, 90,  100, 300 },
            { 125, 90,  100, 300 },
            { 126, 90,   50, 100 },
            { 127, 90,   50, 100 },
            // 门店J：两项金额均为 0，与门店F 构成两个空比值门店，
            //         验证空值置后并列时按最小门店 ID 决胜（F 在前）
            { 128, 100,   0,   0 },
            { 129, 100, 100,   0 },
            { 130, 100,-100,   0 },
            { 131, 100,  50,   0 },
            { 132, 100, -50,   0 },
            // 门店K：两项金额均为最大，验证榜首切换（净额、总额均居首）
            { 133, 110, 400, 600 },
            { 134, 110, 300, 450 },
            { 135, 110, 250, 400 },
            { 136, 110, 200, 300 },
            { 137, 110, 150, 250 },
            // 门店L：常规中等门店，比值恰为 50%
            { 138, 120, 100, 200 },
            { 139, 120,  80, 150 },
            { 140, 120,  60, 120 },
            { 141, 120,  40,  80 },
            { 142, 120,  20,  50 }
        }
    )
```

数据特意包含：

- 门店 A、C 的净销售额相同（900），但总销售额不同，用于验证切换排序指标和同值决胜；门店 B、G 净额同为 800、门店 A、I 总额同为 1,200 提供更多同值案例。
- 门店 H 净额合计为负（-100），用于验证负值排序：净额降序在最后、升序在最前。
- 门店 K 两项金额均为最大，净额、总额降序时均居首，用于区分“榜首不变、中段重排”的切换效果。
- 门店 E 的净销售额为 0，总销售额非零，用于验证真实 0% 的位置。
- 门店 F、J 两项金额均为 0，比值为空，用于验证空值在升序、降序时都置后，以及空值并列时按最小门店 ID 决胜（F 在 J 前）。
- 每个区域 4 家门店、每种店铺类型 6 家门店、每个区域×店铺类型组合 2 家门店，用于验证 A 切换及多选后的重新分组汇总与组内序号。

### 3.3 模型设置

1. 在模型视图创建 `Dim_Demo_Store[Store_ID]` 到 `Fact_Demo_Sales[Store_ID]` 的活动关系。
2. 基数选一对多，交叉筛选方向选单向，从维度到事实表。
3. 若自动检测已经建立该关系，不要再建第二条。
4. `Record_ID`、`Store_ID` 为整数，金额列为固定小数类型。
5. ID 字段设为“不汇总”；金额通过下面的显式度量使用，不直接拖入视觉对象。

## 4. 创建三个基础业务指标

以下度量全部创建在 `Fact_Demo_Sales` 表中，后续字段参数通过这个归属表引用它们。每个 DAX 代码块分别通过“新建度量值”创建，不能把多个定义一次性粘贴到一个度量中。

```dax
Demo Net Sales =
// ========================================
// 度量值: Demo Net Sales
// 中文名: 净销售额
// Display Folder: Demo/Base
// 用途: 汇总当前筛选上下文内的净销售额，表格展示与排序联动共用的基础指标。
// 口径: 对示例事实表 Net_Sales_Amount 求和；含多笔负数调整记录，直接代数相加。
// 依赖: Fact_Demo_Sales[Net_Sales_Amount]。
// ========================================
    SUM(Fact_Demo_Sales[Net_Sales_Amount])
```

```dax
Demo Gross Sales =
// ========================================
// 度量值: Demo Gross Sales
// 中文名: 总销售额
// Display Folder: Demo/Base
// 用途: 汇总当前筛选上下文内的总销售额，表格展示与排序联动共用的基础指标。
// 口径: 对示例事实表 Gross_Sales_Amount 求和。
// 依赖: Fact_Demo_Sales[Gross_Sales_Amount]。
// ========================================
    SUM(Fact_Demo_Sales[Gross_Sales_Amount])
```

```dax
Demo Net Gross Ratio =
// ========================================
// 度量值: Demo Net Gross Ratio
// 中文名: 净销售额 / 总销售额
// Display Folder: Demo/Base
// 用途: 当前分组的净额合计除以总额合计，是分组级比值，不是逐行比值的平均数。
// 口径: DIVIDE 是安全除法，分母为 0 或为空时返回 BLANK()，不伪造为 0%；
//       净额为 0、分母非零时返回真实的 0%。
// 依赖: [Demo Net Sales]、[Demo Gross Sales]。
// ========================================
    DIVIDE([Demo Net Sales], [Demo Gross Sales])
```

| 度量                     | 模型格式     | Display Folder |
| ------------------------ | ------------ | -------------- |
| `Demo Net Sales`       | `#,##0.00` | `Demo/Base`  |
| `Demo Gross Sales`     | `#,##0.00` | `Demo/Base`  |
| `Demo Net Gross Ratio` | `0.0%`     | `Demo/Base`  |

保持度量返回数值，不使用 `FORMAT()` 将它们转换成文本，避免数值排序和总计行为改变。

## 5. 创建 A、B 字段参数

**必须通过“建模 → 新建参数 → 字段”创建，再编辑生成的 DAX。不要直接用“新建表”粘贴元组三列来替代。** 字段参数需要 Power BI 自动写入的元数据，普通计算表即使数据外观相同也不一定能驱动字段替换。

使用支持字段参数及 `RANK` 函数的较新版本 Power BI Desktop。若找不到字段参数入口，先核对 Desktop 版本及本地模型编辑能力，不使用纯远程实时连接完成本 Demo。

### 5.1 A：行维度字段参数

1. 新建字段参数，名称填 `O：Param_Demo_Row`。
2. 依次选入 `Dim_Demo_Store` 的 `Store_Name`、`Region`、`Store_Type`（创建时的勾选顺序不影响最终结果，下一步会整体替换公式）。
3. 勾选“将切片器添加到此页面”，完成创建。
4. 将参数表公式替换为以下完整表达式。

```dax
O：Param_Demo_Row =
    {
        // Row_Order 同时决定两件事：
        // ① 切片器选项显示顺序；
        // ② 多选时的行层级顺序 —— 值小者为外层（区域 → 店铺类型 → 门店，粗 → 细）。
        // 如需调整层级顺序，除修改本表外，还必须同步调整 [Demo Row Rank]
        // 中 ISINSCOPE 分支的匹配顺序（先深后浅）。
        ("区域", NAMEOF('Dim_Demo_Store'[Region]), 10),
        ("店铺类型", NAMEOF('Dim_Demo_Store'[Store_Type]), 20),
        ("门店", NAMEOF('Dim_Demo_Store'[Store_Name]), 30)
    }
```

创建后，在模型视图按列职责重命名三列，保留原列及元数据，不删除后重建：

| 生成列职责                 | 最终列名       |
| -------------------------- | -------------- |
| 第一列，参数显示名称       | `Row_Label`  |
| 第二列，字段引用，通常隐藏 | `Row_Fields` |
| 第三列，参数顺序，通常隐藏 | `Row_Order`  |

将 `Row_Label` 按 `Row_Order` 排序，切片器字段使用 `O：Param_Demo_Row[Row_Label]`。

| 生成列职责   | 最终列名          |

## 7. 创建联动与排序度量

以下八个辅助度量也创建在 `Fact_Demo_Sales`，Display Folder 设为 `Demo/Control`。除排序序号和状态卡外，不放入业务表格列区域。

### 7.1 C 候选项是否可用

```dax
Demo Sort Metric Available = 
// ========================================
// 度量值: Demo Sort Metric Available
// 中文名: C 候选项可用性
// Display Folder: Demo/Control
// 用途: C 切片器“此视觉对象上的筛选器”，等于 1 时候选项可选、等于 0 时不可选。
// 口径: 候选指标 ID 属于 B 当前选中的指标集合时返回 1，否则返回 0。
// 依赖: O：Slicer_Demo_SortMetric、O：Param_Demo_Metric。
// ========================================
    // SELECTEDVALUE —— 列在当前筛选上下文中只有一个不同值时返回该值，否则返回 BLANK。
    // C 为单选切片器，每个候选行都有唯一的 Metric_ID。
    VAR __CandidateID =
        SELECTEDVALUE('O：Slicer_Demo_SortMetric'[Metric_ID])
    // VALUES —— 返回列在当前筛选上下文中的去重值表。
    // B 是独立的字段参数表，不处于 C 的行作用域中，
    // 此处读到的是 B 切片器选中的全部 Metric_Order。
    VAR __AllowedIDs =
        VALUES('O：Param_Demo_Metric'[Metric_Order])
    RETURN
        IF(
            // ISBLANK —— 判断表达式是否为空；IN —— 判断标量是否属于值表。
            NOT ISBLANK(__CandidateID)
                && __CandidateID IN __AllowedIDs,
            1,
            0
        )
```

将此度量放到 **C 切片器本身**的“此视觉对象上的筛选器”，设置等于 1。不要放到页面级筛选器，也不要误放到主表格上。

这里使用 `VALUES` 即可：C 按自己的候选指标分组，B 是独立的字段参数表，不处于 C 的当前分组中。不需要清除 B 筛选，也不能对 B 使用 `ALL`，否则会把三个指标全部放回候选。

### 7.2 实际生效的排序指标 ID

```dax
Demo Effective Sort Metric ID =
// ========================================
// 度量值: Demo Effective Sort Metric ID
// 中文名: 实际生效的排序指标 ID
// Display Folder: Demo/Control
// 用途: 计算排序时实际使用的指标 ID。C 的旧选择可能已不在 B 展示范围内，
//       排序相关度量统一通过本度量取值，不直接读 C 的 SELECTEDVALUE。
// 口径: C 已选择且该选择仍属于 B 当前选中的指标时，沿用 C 的选择；
//       否则回退到可用指标中 ID 最小的一个（净销售额 → 总销售额 → 比值）。
// 依赖: O：Slicer_Demo_SortMetric、O：Param_Demo_Metric。
// ========================================
    // B 清空选择等价于不限制指标，此时三个 ID 全部可用，回退结果与沿用 C 选择一致。
    // __AllowedIDs 受 B 对 C 的 Filter 交互影响，只包含 B 仍展示的指标。
    VAR __AllowedIDs =
        VALUES('O：Slicer_Demo_SortMetric'[Metric_ID])
    VAR __RequestedID =
        SELECTEDVALUE('O：Slicer_Demo_SortMetric'[Metric_ID])
    VAR __RequestedIsAllowed =
        NOT ISBLANK(__RequestedID)
            && __RequestedID IN __AllowedIDs
    RETURN
        IF(
            __RequestedIsAllowed,
            __RequestedID,
            // MINX —— 对值表逐行求表达式的最小值，用作回退项（ID 最小的可用指标）。
            MINX(__AllowedIDs, 'O：Slicer_Demo_SortMetric'[Metric_ID])
        )
```

回退优先级为净销售额 → 总销售额 → 比值，仅在 B 当前包含的指标中选择。

| B 已选                 | C 原选择         | 实际排序指标 |
| ---------------------- | ---------------- | ------------ |
| 净销售额、总销售额     | 总销售额         | 总销售额     |
| 净销售额、总销售额     | 比值，旧选择     | 净销售额     |
| 总销售额               | 净销售额，旧选择 | 总销售额     |
| 比值                   | 未选择           | 比值         |
| 清除 B，三个指标都有效 | 总销售额         | 总销售额     |

不要让排序度量直接使用 C 的 `SELECTEDVALUE` 而跳过本度量，否则旧选择可能继续按 B 未展示的指标排序。

### 7.3 当前行的排序业务值

```dax
Demo Sort Value =
// ========================================
// 度量值: Demo Sort Value

// Display Folder: Demo/Control

// 口径: 10=净销售额，20=总销售额，30=净销售额/总销售额；未匹配时返回 BLANK。
// 依赖: [Demo Effective Sort Metric ID]、[Demo Net Sales]、[Demo Gross Sales]、
```

### 7.4 空值标识

```dax
Demo Sort Blank Flag =
// ========================================
// 度量值: Demo Sort Blank Flag
// 中文名: 空值标识
// Display Folder: Demo/Control
// 用途: 排序的第一关键字，保证业务值为空的行在升序、降序时都排在末尾。
// 口径: ISBLANK —— 判断表达式是否为空；非空返回 0、空返回 1，
//       配合 ASC 排序即实现“空值置后”。
// 差异: v1.2 修正取值方向。v1.0/v1.1 写法为 IF(ISBLANK(...), 0, 1)，
//       空值行 flag=0 反而排在最前，与第 9.3 节“空值置后”的预期矛盾；
//       本版改为空值=1，行为与第 9 节预期一致。
// 依赖: [Demo Sort Value]。
// ========================================
    IF(ISBLANK([Demo Sort Value]), 1, 0)
```

它作为排序的第一关键字：非空为 0、空为 1，始终升序，保证空值不会在业务升序时跑到最前。

### 7.5 将业务方向转换为统一的升序比较值

```dax
Demo Sort Signed Value =
// ========================================
// 度量值: Demo Sort Signed Value
// 中文名: 方向归一化排序值
// Display Folder: Demo/Control
// 用途: 把升序/降序统一转换为升序比较。视觉对象始终按序号升序排列，
//       降序需求通过取相反数实现，因此无需改动视觉排序设置。
// 口径: D 选“升序”保留原值，选“降序”取相反数；业务值为空时仍返回空，
//       空值的先后交给 [Demo Sort Blank Flag] 控制。
// 依赖: [Demo Sort Value]、O：Slicer_Demo_SortDirection。
// ========================================
    VAR __Value = [Demo Sort Value]
    // D 未被选择时默认按“降序”处理。
    VAR __Direction =
        SELECTEDVALUE('O：Slicer_Demo_SortDirection'[Direction_ID], "DESC")
    RETURN
        IF(
            ISBLANK(__Value),
            BLANK(),
            IF(__Direction = "ASC", __Value, -__Value)
        )
```

升序保留原值，降序取相反数；这只影响排序辅助值，不修改表格里的三个业务度量。

### 7.6 同值决胜键

```dax
Demo Row Tie Key =
// ========================================
// 度量值: Demo Row Tie Key
// 中文名: 同值决胜键
// Display Folder: Demo/Control
// 用途: 排序的第三关键字。业务值完全相同时，按分组内最小门店 ID 升序决胜。
// 口径: MIN —— 取列在当前筛选上下文中的最小值。门店层为该店 ID；
//       区域、店铺类型层为该分组最小门店 ID；多选组合行中父级筛选随行继承，
//       决胜键为该组合内的最小门店 ID。
```

门店级为该店 ID，区域级为该区域最小门店 ID，店铺类型级同理。在这份样本中不同分组的该值不同，因此不会出现无法决定顺序的并列。

### 7.7 排序序号

```dax
Demo Row Rank = 
// ========================================
// 度量值: Demo Row Rank
// 中文名: 排序序号（组内重启）
// Display Folder: Demo/Control
// 用途: 生成表格“排序序号”列的数值。视觉对象始终按本度量升序排列，
//       C（排序指标）、D（排序方向）改变的是本度量的计算结果，从而联动改变行顺序。
// 口径: 1. ISINSCOPE 按层级“先深后浅”匹配当前行层级（门店 → 店铺类型 → 区域），
//          命中的第一个分支即当前行所处层级。
//       2. RANK 候选集 = ALLSELECTED(当前层级列)。ALLSELECTED 只移除当前层级列
//          自身的行筛选，保留更外层已选字段的父级筛选，因此候选集恰好是
//          “同一父组下的兄弟成员”，序号在每个父组内从 1 重新编号。
//       3. 组内排序键依次为：空值置后 → 业务值（升序原值/降序取负）→ 最小门店 ID。
//       4. 总计行不处于任何行字段作用域内，序号返回空。
// 差异: v1.1 移除 v1.0 的 HASONEVALUE 单选守卫；分支匹配顺序改为先深后浅。
//       A 单选一个行维度时没有父级筛选，组内序号即全局序号，行为与 v1.0 一致。
// 依赖: [Demo Sort Blank Flag]、[Demo Sort Signed Value]、[Demo Row Tie Key]、
//       Dim_Demo_Store。
// ========================================
    // ① ISINSCOPE —— 判断列是否处于当前行的作用域内。
    //    多选时叶子行会同时命中多个已选字段，因此必须按参数表层级顺序
    //    “先深后浅”匹配，先检查最深一级“门店”。
    SWITCH(
        TRUE(),
        ISINSCOPE('Dim_Demo_Store'[Store_Name]),
            // 门店层（最深）：候选 = ALLSELECTED(门店列)，
            // 保留区域、店铺类型等外层父级筛选 → 同一父组内的门店。
            RANK(
                DENSE,
                ALLSELECTED('Dim_Demo_Store'[Store_Name]),
                ORDERBY(
                    [Demo Sort Blank Flag], ASC,
                    [Demo Sort Signed Value], ASC,
                    [Demo Row Tie Key], ASC
                )
            ),
        ISINSCOPE('Dim_Demo_Store'[Store_Type]),
            // 店铺类型层：未选门店时的最深层级，
            // 保留区域父级筛选 → 同一区域内的店铺类型。
            RANK(
                DENSE,
                ALLSELECTED('Dim_Demo_Store'[Store_Type]),
                ORDERBY(
                    [Demo Sort Blank Flag], ASC,
                    [Demo Sort Signed Value], ASC,
                    [Demo Row Tie Key], ASC
                )
            ),
        ISINSCOPE('Dim_Demo_Store'[Region]),
            // 区域层（最浅）：无更外层父级，候选即全部区域。
            RANK(
                DENSE,
                ALLSELECTED('Dim_Demo_Store'[Region]),
                ORDERBY(
                    [Demo Sort Blank Flag], ASC,
                    [Demo Sort Signed Value], ASC,
                    [Demo Row Tie Key], ASC
                )
            ),
        // 总计行：三个字段均不在作用域内。
        BLANK()
    )
```

这是**模型度量**，不是“新建视觉计算”。`ORDERBY` 内的度量在候选行上下文中求值，不要把 `[Demo Sort Signed Value]` 先缓存成当前单行标量，再把该标量用于所有候选。

`ALLSELECTED` 只移除当前层级列自身的行筛选、保留外层父级筛选，这是“组内序号”的实现基础。A 切换或多选后，对应分支按当前层级重新计算分组指标，而不是给门店排好名后再把名次累加到区域。

注意：

- 表格字段区只放 A 参数提供的行分组字段（多选时自动展开为多列），不另加门店 ID、区域、店铺类型等静态分组列。
- 不对三个源行字段额外设置隐藏排序列；列级 `ALLSELECTED` 依赖“无按列排序”的前提，如未来新增必须重新验证。
- 单选一个行维度时没有父级筛选，组内序号即全局序号，门店级六种排序结果与 9.3 节完全一致（回归基准）。
- 多选时序号在每个父组内从 1 重新编号；组与组之间的先后顺序由外层字段的默认排序决定，不再按业务指标排序，这是组内序号语义的固有边界。
- 序号并列的行（不同父组各有自己的 1、2……）依赖视觉对象排序的次级顺序聚到各自父组下，该次级排序行为需在 Desktop 实测确认；不符合预期时参考第 11 节排错。
- 表格视觉对象没有父级小计行，序号只出现在叶子组合行；区域、店铺类型的汇总值需通过单选对应维度或总计行查看。
- A 被清空等价于三个字段全部进入行层级，最深层级为门店，序号仍正常计算；多选是受支持状态，不再是 v1.0 的非法状态。
- 辅助序号本身非空，会让仅比值为空的门店 F 仍然出现在表格中，这是本 Demo 用于验证空值置后的预期行为。
- 总计行不处于任一实际行字段的作用域中，序号返回空。基础指标总计仍正常显示。

### 7.8 排序状态卡

```dax
Demo Sort Status = 
// ========================================
// 度量值: Demo Sort Status
// 中文名: 排序状态卡
// Display Folder: Demo/Control
// 用途: 卡片视觉对象文本，展示实际生效的行层级、排序指标、排序方向与回退提示。
// 口径: 行层级按 Row_Order 升序拼接（清空 A 等价于三个字段全部进入层级）；
//       实际排序指标取 [Demo Effective Sort Metric ID]，与 C 勾选外观无关；
//       C 未选择或旧选择失效时输出回退提示。
// 差异: v1.1 移除“请在 A 中单选一个行维度”分支，新增行层级展示。
// 依赖: [Demo Effective Sort Metric ID]、O：Param_Demo_Row、
//       O：Slicer_Demo_SortMetric、O：Slicer_Demo_SortDirection。
// ========================================
    // ① 拼接当前行层级名称。
    //    CONCATENATEX(表, 表达式, 分隔符, 排序列, 排序方向) —— 按指定顺序迭代并拼接文本。
    //    对整数顺序列取 VALUES 再映射为中文名，不直接读参数显示名称列，
    //    规避字段参数显示名称列的复合键限制。
    VAR __RowLevels =
        CONCATENATEX(
            VALUES('O：Param_Demo_Row'[Row_Order]),
            SWITCH(
                'O：Param_Demo_Row'[Row_Order],
                10, "区域",
                20, "店铺类型",
                30, "门店"
            ),
            " → ",
            'O：Param_Demo_Row'[Row_Order], ASC
        )
    // ② 实际生效的排序指标与方向。
    VAR __EffectiveID = [Demo Effective Sort Metric ID]
    VAR __RequestedID =
        SELECTEDVALUE('O：Slicer_Demo_SortMetric'[Metric_ID])
    VAR __MetricLabel =
        SWITCH(
            __EffectiveID,
            10, "净销售额",
            20, "总销售额",
            30, "净销售额/总销售额"
        )
    VAR __Direction =
        SELECTEDVALUE('O：Slicer_Demo_SortDirection'[Direction_ID], "DESC")
    VAR __DirectionLabel = IF(__Direction = "ASC", "升序", "降序")
    // ③ C 选择无效时的回退提示。
    VAR __Notice =
        SWITCH(
            TRUE(),
            ISBLANK(__RequestedID), "C 未单选，已使用当前展示指标中的首项。",
            __RequestedID <> __EffectiveID, "C 原选择已失效，已使用当前展示指标中的首项；请重新选择 C。",
            ""
        )
    RETURN
        __Notice
            & "行层级：" & __RowLevels
            & "；当前按「" & __MetricLabel & "」" & __DirectionLabel
            & "；序号在每组内从 1 重新编号，空值置后，同值按分组最小门店 ID 升序。"
```

此卡片展示的是**实际生效的排序设置与行层级**。清空 A 时 `VALUES('O：Param_Demo_Row'[Row_Order])` 返回全部三个 ID，层级显示为“区域 → 店铺类型 → 门店”，与三个字段全部选中的显示一致。回退不会修改 C 勾选；如果以后 B 重新包含 C 保留的旧选择，该旧选择可能再次生效，这是按当前状态重新判定的结果。

## 8. 配置视觉对象和交互

### 8.1 主表格字段区域

插入原生“表格”，按以下顺序放入字段：

| 顺序 | 字段                                   | 操作                                                          |
| ---- | -------------------------------------- | ------------------------------------------------------------- |
| 1    | `[Demo Row Rank]`                    | 此视觉对象中重命名为“排序序号”，格式整数                    |
| 2    | `O：Param_Demo_Row[Row_Label]`       | 作为字段参数使用，实际展开成 A 选中的行分组字段，多选时为多列 |
| 3    | `O：Param_Demo_Metric[Metric_Label]` | 作为字段参数使用，实际展开成 B 选中的业务度量                 |

字段井必须使用已识别的字段参数，不是把第二列的 `NAMEOF` 字符串作为普通文本放入表格。正确效果是看到门店 A、门店 B 等成员及真实金额，而不是看到“门店”“净销售额”作为重复的数据记录。A 多选时，行字段参数自动展开为多个行分组列，按 `Row_Order` 顺序排列（区域最左、门店最右），不要手工调整列序。

固定设置：

1. 按“排序序号”**升序**排序一次；以后切换 A、C、D 不需要修改视觉排序。
2. 开启“渐变布局”（Stepped layout），多选时呈现层级外观；关闭后为平铺组合列，序号语义不变。
3. 将排序序号列保留为正常可见的窄列，位置在最左。
4. 开启总计行，两个金额为合计，比值为合计净额除以合计总额；总计行序号为空。
5. 关闭业务金额显示单位自动缩放，金额两位小数，比值一位小数百分比。
6. 不新增 TopN、零值隐藏或 `Demo Sort Metric Available = 1` 之类的主表格筛选。
7. 不添加额外静态分组列，不将基础金额列作为隐式度量放入表格。

### 8.4 推荐演示顺序

1. 保持默认设置，展示门店 A、C 净额相同但次序稳定（A 在 C 前），榜首为门店 K。

5. B 增加比值，C 出现比值候选；选择比值并切换 D。
6. A 恢复门店，观察门店 E 的 0%、门店 H 的负比值和门店 F、J 的空值位置不同。
7. 保持 C 选比值，再在 B 取消比值；状态卡提示回退，表格不得继续按比值排序。必要时在 C 手动选择一个当前可用指标。

9. A 改选“店铺类型 + 门店”，验证另一层级组合下序号按店铺类型分组重新编号。
10. A 选“区域 + 店铺类型”，每个组合恰好 2 家门店，序号为 1、2；再清空 A，状态卡显示完整层级提示，序号仍按门店层计算。

## 11. 排错与使用边界

| 现象                               | 检查项                                                                                             |
| ---------------------------------- | -------------------------------------------------------------------------------------------------- |
| B 选两个指标，C 仍能正常选择三个   | B → C 是否为 Filter；Available 是否放在 C 视觉筛选且等于 1；是否只剩旧选择被保留显示              |
| C 切换导致 B 或表格只剩一个指标    | 是否误建了 B/C 关系，或误用同一个参数表同时承载 B 和 C                                             |
| 状态卡变化但表格顺序不变           | 表格是否仍按排序序号升序；C/D → 表格是否开启 Filter                                               |
| 单选时序号全为 1 或每组重新编号    | 是否额外放了静态分组字段，或给源行字段添加了隐藏排序列                                             |
| 多选时序号全为 1                   | 是否处于每个父组仅一行的层级（清空 A 后看区域 + 店铺类型组合是否仅一家门店）；父级筛选是否被误清除 |
| 多选后行没有按父组聚在一起         | 序号并列时视觉对象的次级排序是否符合预期（实测项）；外层字段列是否被移到最右                       |
| 矩阵中行顺序不随 C、D 变化         | 矩阵不支持按度量排序行（见 1.2 限制三）；改回表格 + 渐变布局                                       |
| 提示字段参数列属于复合键           | 是否直接读取了参数显示名称；按方案改用整数顺序列                                                   |
| 表格显示 NAMEOF 字符串而非实际字段 | 是否通过“新建参数 → 字段”创建，是否保留字段参数元数据                                           |
| 总计比值不对                       | 是否用了逐行比值平均，或将度量转成文本后另行聚合                                                   |
| 比值为空的 F 门店没有显示          | 是否移除了排序序号列，或新增了空值隐藏筛选                                                         |
| 比值为空的 F 门店跑到最前          | 是否遗漏`Demo Sort Blank Flag`，或直接用金额式数值排序而未处理空值                               |
| 改 B 后 C 的勾选没有自动变化       | 原生选择状态限制；检查实际排序与状态卡，不用勾选外观替代有效性校验                                 |

本方案不使用动态计算列做排名：计算列只在模型刷新时更新，不能响应切片器。字段参数计算表本身是静态配置，动态部分来自查询时的筛选上下文和度量。

若未来改为多层矩阵、增加行字段、增加外部筛选或隐藏辅助列，必须重新设计和验收，不直接将本 Demo 的单维排名视为通用层级排序算法。

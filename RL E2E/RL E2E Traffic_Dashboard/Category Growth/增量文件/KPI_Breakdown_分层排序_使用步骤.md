# KPI Breakdown 分层排序使用步骤

> 用途：在现有 Power BI 矩阵上安装排序方案，不重建整个报表。
>
> 创建日期：2026-09-24。本文仅新增操作说明；未修改 SQL、原解决方案或实际模型。

## 先回答：矩阵可以直接按值排序吗？

可以按数值度量排序，但要区分三个问题：

| 情况 | 能否直接操作 |
|---|---|
| 没有列分组，独立数值度量放在“值”区域 | 通常可以点击度量列头，或通过排序菜单选择该度量升序/降序 |
| 当前矩阵的列是 MetricGroup → MetricName | 原生矩阵不一定支持点击任意叶列排序；本方案使用最右侧数值 Grand Total 作为排序入口 |
| 前两层按固定规则，只有第三层按 Cost MOB% Total | 不能仅靠“全矩阵按 Cost MOB% Total 降序”表达，需要分层排序度量 |

你的原 `[KPI Breakdown Cell Display]` 使用 FORMAT 返回文本，不能把看上去是百分比的显示文本当作可靠的数值排序依据。

本方案最终也是“按值排序”：按辅助数值降序。区别是这个辅助值在前两层返回固定序号的负值，在第三层返回根据 Cost MOB% Total 算出的名次负值。因此不需要手工给每一层分别点一次排序。

这里不承诺点击现有 Cost MOB% 分组下面的 Total，就能直接完成全部需求；带列分组的排序入口仍须在实际 Desktop 版本验证。

## 操作前准备

1. 将 `.pbix` 另存一份测试副本。只复制页面不能隔离 SQL 和模型变更。
2. 保留原来的六个业务度量值，不删除、不重新创建。
3. 准备同目录的两个文件：
   - [完整 SQL](./Brand-Category-Framework排列组合_分层排序.sql)：用于替换原行维度查询的 SQL。
   - [完整解决方案](./KPI_Breakdown_matrix_solution_分层排序.md)：只需要复制第 5 节的五个新增度量；第 4 节旧度量代码可以跳过。

整个过程只有五步：替换 SQL → 新建五个度量 → 绑定动态格式 → 替换矩阵“值” → 选择总计降序。

## 第一步：替换原行维度查询的 SQL

在 Power BI Desktop 中：

1. 点击“主页 → 转换数据”。
2. 在 Power Query 左侧找到模型行表 `'Brand->Category->Framework'` 对应的原查询。
3. 在原查询配置 SQL 的位置，用新 SQL 文件的全部内容替换旧 SQL。
   - 如果“源”步骤的齿轮能够编辑 SQL，在该对话框中替换。
   - 如果 SQL 写在高级编辑器中，只替换 M 代码里的 SQL 字符串，并保留连接和后续 M 步骤；不要把整个高级编辑器内容替换成裸 SQL。
4. 查询名称、模型表名和原来的 Level 字段名保持不变。
5. 检查预览结果，然后点击“关闭并应用”。

**完成标志：**原行表出现 `L1_Sort`、`L2_Sort`、`L3_Sort` 等新增列，且这三个字段为整数类型。

注意：
- 如果“选择列”等后续步骤剔除了新增字段，需要保留这些新增列。
- 不用新建第二张行维度表，不用给行表新增事实表关系。
- 这三个排序字段不拖入矩阵行区域，也不直接绑定为 Level 字段的“按列排序”。如果旧模型已经存在这种绑定，在测试副本中解除。

## 第二步：新建五个度量值

打开完整解决方案第 5 节。在原存放度量值的表上，右键“新建度量值”，按下表顺序逐个复制代码：

| 顺序 | 文档位置 | 度量值名称 |
|---|---|---|
| 1 | 5.1 | KPI Breakdown Sort Context Valid |
| 2 | 5.2 | KPI Breakdown Sort Cost MOB Total |
| 3 | 5.3 | KPI Breakdown Sort Value |
| 4 | 5.4 | KPI Breakdown Matrix Value |
| 5 | 5.5 | KPI Breakdown Matrix Format |

每次复制一个完整 DAX 代码块，从“度量值名称 =”开始；不要复制 Markdown 的代码围栏。一次新建一个度量，不是新建列或新建表。

**完成标志：**五个度量都能保存，无公式错误；原有六个度量仍保留。

## 第三步：给 Matrix Value 绑定动态格式

1. 在右侧字段列表中选中 `KPI Breakdown Matrix Value`。
2. 在“度量值工具/属性”中，将“格式”选择为“动态”。
3. 切换到“格式字符串表达式”，只输入下面这一行：

```dax
[KPI Breakdown Matrix Format]
```

注意：这行输入在“格式字符串表达式”中，不要覆盖 Matrix Value 原本的计算公式，也不需要另建一个度量。

这一步让数值仍然是数值，但显示继续使用原来的 bp、%、小数和 `-`。

如果看不到“动态”选项，先确认 Desktop 版本和模型编辑权限，不要用 FORMAT 重写 Matrix Value 的数值公式来代替这一步。

## 第四步：替换矩阵“值”区域的度量

选中测试副本中的矩阵，在“生成视觉对象”的字段区域中这样设置：

| 区域 | 操作后的内容 |
|---|---|
| 行 | 保持 `'Brand->Category->Framework'` 的 Total → Level 1 → Level 2 → Level 3 |
| 列 | 保持 `Dim_ColMetric_KpiBreakdown` 的 MetricGroup → MetricName |
| 值 | 仅放入 `KPI Breakdown Matrix Value` |

具体操作：

1. 从矩阵“值”中移出原 `KPI Breakdown Cell Display`。
2. 将新 `KPI Breakdown Matrix Value` 拖到“值”中。
3. 其他四个新增度量都不要拖进“值”，它们只是计算或格式依赖。
4. 如果原颜色或图标绑定随替换被清除，重新绑定原字体颜色、背景色和图标配置；规则仍基于原业务数值，不基于排序分数。

只是从视觉对象中移出原 Display，不是从模型中删除它；新的动态格式仍会调用它。

## 第五步：开启最右侧总计，并按它降序

先固定一个容易检查的场景：

- 平台单选 `TM`，界面标签可能显示为 `Tmall`。
- Scenario 单选 `Brand->Framework->Category`。
- 两个切片器均开启单选，确认与矩阵的交互为“筛选”。

然后设置矩阵：

1. 打开矩阵“格式”面板中的总计相关设置，开启跨所有指标的最右侧横向 Grand Total。
   - 不同版本属性名称可能不同，以“每行最右侧新增一个 Total 单元格”为准。
   - 不是底部总计行，也不是 Cost MOB% 分组下面原有的 Total。
2. 关闭各指标组多余的小计，但保留上述最右侧 Grand Total。
3. 暂时保持格式度量中的 `__HideSortScore = FALSE()`，不要隐藏辅助数字。
4. 展开业务第一层，最右侧应能看到 `-10、-20……` 等分数。
5. 点击最右侧总计数值列的列头，切换为“降序”并确认排序箭头。若用“…”排序菜单，选择该数值度量对应的总计排序入口，不选行标签。
6. 通过行前面的“＋”逐级展开到第三层，保留父节点；不要使用“转到层次结构中的下一级”移除父层。

### 哪个 Total 才是排序入口？

| 看到的位置 | 是否作为本方案排序入口 |
|---|---|
| 最左侧行标题中的 Total | 否 |
| 最底部的总计行 | 否 |
| Cost MOB% 分组下面的 Total 业务列 | 否 |
| 新开启的最右侧跨所有指标的 Grand Total 列 | 是 |

**完成标志：**第一、第二层的辅助分数是负静态序号；第三层同一父节点内部是 `-1、-2、-3……`。选择降序后，-1 在 -2 前，-10 在 -20 前。

## 做完后如何检查？

以 `Brand->Framework->Category` 为例：

| 层级 | 应看到的顺序 |
|---|---|
| 第一层 Brand | M Polo → W Polo → Lauren → RRL → CW → CL → PL → HM；只显示实际存在的项 |
| 第二层 Framework | Foundation → Acceleration → Complementary → Other；只显示实际存在的项 |
| 第三层 Category | 同一 Brand、Framework 内按 Cost MOB% Total 从大到小 |

再检查三件事：

1. 更换日期，第三层随指标重新排序；前两层重要性顺序不变。
2. 切换到 `Category->Framework->Brand`，第三层 Brand 按指标排序，不再按品牌重要性。
3. 原业务数值与旧矩阵一致；同值按名称字母序，空值排在非空值之后。

## 常见卡点

| 现象 | 先检查 |
|---|---|
| 提示找不到 L1/L2/L3_Sort | SQL 是否替换、是否关闭并应用、后续 Power Query 步骤是否保留新增列 |
| 新增度量后矩阵全空 | 平台和 Scenario 是否单选，尤其 Scenario_Type 必须有直接单值筛选；表名是否保持原样 |
| 百分比变成普通小数 | 动态格式是否绑定到 Matrix Value 的格式表达式 |
| 每个指标下多出五列 | “值”区域是否误放了所有辅助度量；这里只留 Matrix Value |
| 全部仍按名称排序 | 是否真正按最右侧数值 Grand Total 降序，而不是按行标签 |
| 找不到最右侧总计或点它不能排序 | 提供矩阵字段区域、格式面板及 Desktop 版本信息，核实本机排序入口，不继续假定已生效 |

先让可见辅助列的排序正常，再考虑隐藏数字。将 `__HideSortScore` 改为 TRUE 只是试验隐藏字符，并不删除列宽或表头；不要直接关闭总计列并假定排序一定保持。

本文是安装操作指南，不代表实际 Desktop 已验证成功。完整口径、模型前提、平台覆盖范围、性能及回退说明见同目录完整解决方案。
